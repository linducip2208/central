# MBG Central Kitchen

منصة ERP متكاملة لإدارة عمليات المطابخ المركزية ضمن برنامج الوجبات الغذائية المجانية (MBG)، مع دعم عزل بيانات المؤسسات.

**التقنيات:** Laravel 13 · PHP 8.3 · MySQL 8 · Blade · Tabler · Sanctum · Spatie Permission · Activity Log

## الإصدار الحالي

**v1.0 — نظام ERP للمطبخ المركزي**

يتضمن الإصدار الحالي النواة التشغيلية التالية:

- عزل البيانات بين المؤسسات
- إدارة المؤسسة والمطبخ المركزي ووحدات المطبخ والمستودعات
- إدارة الموردين والمدارس والمستفيدين
- تصفية المستفيدين حسب الحساسية الغذائية
- المواد والمنتجات والوحدات وتحويل الوحدات
- إدارة القوائم والوصفات والقيمة الغذائية
- تخطيط الطلب وحساب الاحتياجات حسب الوصفات
- طلبات الشراء وأوامر الشراء وإيصالات الاستلام
- الاستلام الجزئي
- دفتر حركة المخزون مع المعاملات وقفل الصفوف
- الدفعات وتواريخ الانتهاء وFEFO
- حركات المخزون والجرد والتحويل بين المستودعات وحجز المخزون وتحريره
- تخطيط الإنتاج وأوامر الإنتاج
- حساب احتياجات المواد واستهلاك الإنتاج
- مخرجات الإنتاج وحساب التكلفة
- مراقبة الجودة PASS/FAIL/CONDITIONAL
- التعبئة والتوزيع
- التسليم وتتبع السائق عبر GPS
- إثبات التسليم بالصور
- إدارة الهدر
- متوسط التكلفة والتقارير التشغيلية
- إشعارات سير العمل
- سجل التدقيق
- RBAC وعزل الصلاحيات حسب المؤسسة
- API v1 باستخدام Sanctum للمصادقة والمخزون وتتبع التسليم
- واجهة Responsive مبنية على Tabler
- اختبارات آلية واختبارات Regression

## سير العمل الأساسي

```
الطلب
 → تفجير الوصفة
 → طلب شراء
 → أمر شراء
 → استلام البضائع
 → المخزون + الدفعات + FEFO
 → تخطيط الإنتاج
 → أمر الإنتاج
 → استهلاك المواد
 → مراقبة الجودة
 → التعبئة
 → التوزيع
 → التسليم
 → المدرسة / المستفيد
 → التقارير + التكلفة + التدقيق
```

## محرك المخزون

تتم جميع عمليات تغيير المخزون الفعلية من خلال خدمة مركزية:

- معاملات قاعدة البيانات
- `lockForUpdate()`
- دفتر حركات غير قابل للتعديل
- FEFO
- التحكم في الدفعات والانتهاء
- تحويل الوحدات
- العمليات الجزئية
- حجز المخزون
- منع التكرار Idempotency
- فحوص اتساق المخزون
- حساب تكلفة الإنتاج من دفتر الاستهلاك

## API v1

يوفر النظام حالياً API محمياً بواسطة Sanctum من أجل:

- تسجيل الدخول والخروج بالرمز
- بيانات المستخدم الحالي
- ملخص المخزون
- المخزون منخفض الكمية
- المخزون القريب من الانتهاء
- حركات المخزون
- قائمة عمليات التسليم للسائق
- تتبع GPS للتسليم

تبقى عمليات تغيير المخزون من خلال واجهة الويب لضمان استخدام نفس دفتر المخزون وقواعد FEFO.

## مبادئ التطوير

- تمر جميع تغييرات المخزون عبر خدمة دفتر المخزون.
- يجب عزل بيانات كل مؤسسة في كل استعلام وعملية.
- استخدام Policies وPermissions للتفويض.
- استخدام Transactions في العمليات الحساسة.
- منع الترحيل المكرر باستخدام Idempotency.
- استخدام FEFO للمخزون القابل للتلف.
- إبقاء الحسابات التجارية قابلة للاختبار خارج Controllers.
- منع N+1 والاستعلامات الثقيلة غير المنضبطة.
- الحفاظ على اتساق واجهة Tabler.
- إضافة اختبارات آلية لكل سير عمل حساس.
- عدم اعتبار أي ميزة مكتملة مع وجود TODO أو Placeholder أو مسار مكسور.
